01 Zero-Trust Trust-Boundary Architecture

The defining insight of Palomar-style verification is asymmetric trust: you never need to trust the AI agent, its prompt, its proof search heuristics, or its 50,000 lines of intermediate lemmas. You only audit the short specification and the small deterministic checker at the boundary.

Why this works in real engineering (not just pure math): Traditional formal verification fails in industry because writing proofs takes 10× longer than writing code. Conversely, naive LLM code review fails because hallucinations slip past tests. Separating a human-written 100-line spec from an agent-synthesized proof checked by two independent kernels gives us machine-checked certainty without human proof-engineering bottlenecks.

Domain Specification: ERC-4626 Vault & AMM Solvency

Model contract state transitions (deposit, withdraw, swap, accrueFee) over exact unbounded integers / fixed-point rationals plus explicit UInt256 bounds. Prove that every reachable trace preserves solvency, share-price monotonicity, and zero inflation-attack extractability.

  • Key Invariants: Vault solvency (totalAssets ≥ Σ redeem(shares)), AMM invariant monotonicity (k' ≥ k with floor rounding favoring pool), non-reentrant state isolation.
  • Falsification Pre-Check: Foundry / Hypothesis stateful fuzzing + Z3 bounded 8-step flash-loan attack search before launching Lean provers.
  • Production Bridge: Export Lean reference semantics as executable test oracle; replay 100k Foundry differential traces against live Solidity EVM bytecode.

Domain Specification: Consensus Safety & Crypto Transcripts

Model network nodes, Byzantine faults (|F| < n/3), asynchronous message delivery bags, and cryptographic primitives as abstract collision-resistant hash / unforgeable signature predicates.

  • Key Invariants: Agreement / Election Safety (no two honest nodes commit conflicting blocks at height h), Quorum Intersection, Merkle inclusion/consistency soundness, Noise/TLS handshake key-binding.
  • Falsification Pre-Check: Bounded TLC / Python BFS adversary simulator up to 4 nodes and 6 rounds to catch missing quorum or view-change guards instantly.
  • Production Bridge: Generate deterministic JSON protocol state traces from Rust/Go production nodes and validate every transition step against the Lean transition relation.

03 The 7-Stage Agentic Spec → Proof Loop

Unlike single-shot LLM theorem generation, PCVH treats proof synthesis as a structured, resource-bounded software engineering loop with fast falsification, targeted imports, and deterministic escalation.

Stage 01 · TCB Freeze

Spec Ingestion & Hash Pinning

Hashes Statement.lean, Challenge.lean, lean-toolchain, and lake-manifest.json into spec.lock.json. Extracts every target theorem signature, quantifier structure, and required non-vacuity witness into the task graph.

Stage 02 · Fail Fast

Executable Falsification Pre-Check

Never try to prove a false theorem. Before invoking prover agents, PCVH runs Lean's Plausible / #eval property checks + Python Hypothesis / Z3 bounded search. If a counterexample is found, the harness halts immediately and returns the concrete failing trace to the engineer!

Stage 03 · Decomposition

DAG Lemma Architect

Breaks each Challenge theorem into a shallow DAG of self-contained helper files (Proofs/Lem_*.lean), each with explicit minimal imports (forbidding umbrella import Mathlib) and clear induction / strengthening hypotheses.

Stage 04 · Synthesis

Parallel Prover Workers + LSP Feedback

Spawns isolated worker agents on leaf lemmas. Workers query real Lean 4 goal states via lean --json / Lean LSP and climb a deterministic escalation ladder: omega / simp / grind / aesop → structured calc/induction → premise retrieval → recursive sub-lemma extraction.

Stage 05 · Build Runtime

lean-orch Memory-Aware Build

Directly embeds our Lean 4 Windows/Low-RAM Build Orchestrator: monitors Win32 GetPerformanceInfo commit charge, serializes heavy workers while parallelizing light modules, and auto-retries transient pagefile/mmap faults without crashing consumer workstations.

Stage 06 · Hygiene

Import Shaking & Dead-Code Pruning

Runs native lake shake --fix (for module projects) or our automatic lean-env-fallback analyzer (for standard Lean 4 files) with backup/verify/rollback, shrinking transitive imports and cutting CI rebuild times by 5–20×.

Stage 07 · Zero-Trust Gate

Palomar Dual-Kernel Verification

Copies untrusted Proofs/ + Solution.lean into a clean air-gapped workspace with immutable TCB files stamped on top. Runs static ban scan → Lean 4 build → comparator → lean4export → nanoda → signs proof-attestation.json.

04 Threat Model & Anti-Cheating Defense Matrix

LLM provers are notoriously creative reward-hackers. Every known Lean 4 proof-cheating vector—audited directly against Anthropic's vp-vnp Palomar CI script—must be blocked deterministically.

Filter severity:
Attack / Failure Vector Severity How an Untrusted Agent Could Exploit It Deterministic PCVH Mitigation
Spec Mutation / Weakening Critical Agent edits Statement.lean or Challenge.lean to add False hypothesis or weaken the postcondition. Gate overwrites TCB files from pinned SHA-256 commit before building; comparator asserts exact definitional equality against untouched Challenge.
sorry, admit, Custom axiom Critical Agent leaves hidden sorry in a helper lemma or introduces an unsound axiom. Static AST/regex scan + #print axioms + comparator strict allowlist ([propext, Classical.choice, Quot.sound] only) + nanoda rejection.
native_decide / Compiler Escape Critical Agent uses native_decide, unsafe, @[implemented_by], or Lean.ofReduceBool to bypass kernel type-checking via compiled code. Ban Lean.ofReduceBool & Lean.ofReduceNat from axiom allowlist; reject unsafe/implemented_by/extern in static gate; verified independently by nanoda.
Metaprogramming Env Injection Critical Malicious tactic/macro calls Lean.addDecl or modifies Lean runtime state or exfiltrates secrets during elaboration. Run untrusted elaboration inside networkless OS sandbox (landrun on Linux / restricted Windows Job Object) and re-check exported proof terms in nanoda (zero tactic execution!).
Vacuous Specification High Engineer accidentally writes contradictory preconditions (e.g. n < 0 on Nat), so the invariant holds vacuously for 0 states. Schema requires at least one constructive non-vacuity witness theorem per spec + Stage 2 falsification/reachability check proving nontrivial traces exist.
Model ↔ Production Drift High Lean model is proved sound, but production Solidity/Rust/Python code diverges on an integer rounding or edge case. Mandatory Differential Conformance Bridge: execute Lean reference model against production implementation across 100k+ randomized & regression traces on every PR.
Toolchain / Lakefile Tampering High Agent modifies lakefile.toml or lean-toolchain to point to a patched Lean binary or malicious dependency. lean-toolchain, lakefile.*, and lake-manifest.json are TCB-pinned; Gate builds offline with read-only dependency cache.
Windows Commit-Charge OOM Medium Agent sprays import Mathlib across 30 generated proof files, crashing local & CI builds with failed to read file '*.olean.private'. Linter rejects raw import Mathlib in generated files; lean-orch gates worker concurrency on Win32 commit headroom; Stage 6 runs lake shake automatically.

07 Success Metrics, Cost Envelope & Key Risks

Concrete engineering gates that distinguish a genuinely practical verification tool from an academic demo.

Soundness & Gate Targets

  • 0% false acceptance: 12/12 red-team cheating proofs rejected deterministically.
  • < 60 s CI gate latency: Enabled by targeted imports + lake shake + cached .oleans.
  • 100% reproducible: Offline dual-kernel replay from pinned spec.lock.json.

Agent Economics & Efficacy

  • > 90% bug-spec catch rate: Stage 2 falsifier catches false invariants in <15s before spending prover tokens.
  • ≥ 70% auto-proof rate: On the 40-invariant engineering benchmark without human intervention.
  • < $2 median cost / invariant: Achieved via fast local Lean feedback + small-context lemma decomposition.

Top Risks & Practical Mitigations

  • Spec-writing friction: Provide domain DSL templates & an interactive Spec-Interview assistant (still human-approved & audited!).
  • Hard inductive invariants: Allow engineers to supply a 5-line strengthening hint without writing proof tactics.
  • Model-code gap: Enforce differential trace fuzzing as a co-requirement of the attestation JSON.
